# nx6 OpenWebUI：nx5 两模型聊天入口

页面：<http://nx6.taild500c8.ts.net:18348>。需要Tailscale。
登录后从模型下拉菜单选择 `qwen36-128k` 或 `minicpm-64k`，一次选择一个模型。
默认Qwen，中文界面。nx6只运行WebUI，模型仍在nx5按请求加载、完成后卸载，独占租约和互斥机制不变。
当前OpenAI接口只提供文本聊天，不能通过这个入口上传图片识别或调用工具。

## 登录与私有配置

- 已创建独立的Ivan管理员账号，关闭注册。
- Mac本机：`~/.config/nx5-openwebui/login.txt`（0600）；JSON版本供本地验收脚本使用。
- nx6：`~/.config/nx5-openwebui/login.json`、`runtime.env`（0600），目录0700。
- API密钥只从nx5经SSH传输到nx6私有配置，不进入Git、页面说明或验收日志。
- 登录后可在账号设置修改密码。首次登录可能显示更新日志，关闭即可。

## 部署与模型设置

Open WebUI官方`v0.12.3-slim`，linux/arm64，固定镜像digest见
[release.json](../deploy/openwebui/release.json)，不跟随main/latest自动更新。
容器`nx5-openwebui`仅绑定`100.67.179.113:18348`，重启策略unless-stopped。
数据保存在nx6 `~/.local/share/nx5-openwebui/data`；容器上限1.5GiB RAM和2CPU，不挂载GPU。
初始空闲实测约304MiB。

连接指向`http://100.118.44.27:18347/v1`，服务端使用专用Bearer Key。
[settings.json](../deploy/openwebui/settings.json)关闭Ollama、标题、标签、追问、自动补全和本地模型下载；
长请求超时2700秒。两个模型的输出上限7680，其他采样参数沿用nx5各模型固定配置，思考关闭。

实际网页测试发现：v0.12.3默认会向普通UI聊天注入内置工具，而nx5文本接口明确拒绝tools。
因此通过OpenWebUI自身API，为两个现有模型ID保存了文本能力配置，`builtin_tools=false`，
同时关闭vision、file_context、web_search、image_generation、code_interpreter、terminal。
这些设置写入持久化模型配置，不修改OpenWebUI源代码，不把工具调用伪装成文本请求。
详见[models.json](../deploy/openwebui/models.json)。

部署代码提交：`4b46ced2085df02705b64e9c96c502b11b459dd0`；模型配置和验收在后续提交中记录。
复现顺序（新实例；已有容器或数据会拒绝覆盖）：

```bash
python3 scripts/nx5/deploy-openwebui.py --commit <包含release.json的固定提交>
python3 scripts/nx5/deploy-openwebui.py --commit <同一固定提交> --apply
# 等待容器healthy，再以管理员身份应用模型能力配置
python3 scripts/nx5/configure-openwebui-models.py \
  --profiles deploy/openwebui/models.json --output /tmp/openwebui-models-check.json
```

模型配置通过认证API修改；不直接编辑数据库。重新部署/升级时保留data目录和私有密钥。
停用本实例只需停止`nx5-openwebui`容器，不要删除数据，也无需停nx5推理API。
