# nx6 OpenWebUI：nx5 两模型聊天入口

页面：<http://nx6.taild500c8.ts.net:18348>。需要Tailscale。
登录后从模型下拉菜单选择 `qwen36-128k` 或 `minicpm-64k`，一次选择一个模型。
默认Qwen，中文界面。nx6只运行WebUI，模型仍在nx5按请求加载、完成后卸载，独占租约和互斥机制不变。
当前OpenAI接口只提供文本聊天，不能通过这个入口上传图片识别或调用工具。

## 每条回复的速度统计

刷新页面后，新回复完成时会显示一条统计状态：`生成速度 … token/s · 生成耗时 … 秒 · 总耗时 … 秒`。
总耗时是nx5服务受理至任务完成，包含资源准备、模型加载、输入处理、生成与释放，
不包含浏览器网络和渲染时间。生成TPS和生成耗时直接来自引擎，不能用总耗时替代。
回复下方ⓘ可查看输入/输出token数，以及`decode_tps`、`generation_s`、`prefill_s`、`process_wall_s`、`total_s`。
已有的无usage历史回复不会补造数据。

实现采用OpenWebUI持久化Filter：`nx5_generation_stats`，源码见
[generation_stats.py](../deploy/openwebui/generation_stats.py)。仅绑定两个nx5模型，不启用为全局过滤器。
它请求流式usage，在完成后用原生状态事件展示统计；不更改模型回答、SVG、聊天历史提示词或采样参数。
接口通过独立`timings`扩展返回测量值，标准usage字段保持原语义。
重放同一幂等任务时保留原请求耗时，不重复累加token数。
安装/更新仍使用`configure-openwebui-models.py`，会先部署并启用Filter再保存模型绑定；
升级OpenWebUI保留data目录即可保留此配置，无需改动官方镜像文件。

[release.json](../deploy/openwebui/release.json)，不跟随main/latest自动更新。

### Qwen 鹈鹕参考默认值

按[原仓库的35B-A3B启动配置](https://github.com/bbinwang/pelican-bicycle/blob/b14acbb2ebe9d9be5f0dec3d35d8f4ae6fcaa432/configs/Qwen3.6-35B-A3B-UD-IQ4_XS.config)
核对（提交`b14acbb2ebe9d9be5f0dec3d35d8f4ae6fcaa432`）。这是该仓库的测试配置，不是所有模型共用的默认值。

| 参数 | 默认值 | 生效位置 |
| --- | --- | --- |
| temperature | 0.7 | OpenWebUI模型配置和后端 |
| top_p | 0.8 | OpenWebUI模型配置和后端 |
| presence_penalty | 1.5 | OpenWebUI模型配置和后端 |
| top_k / min_p / repeat_penalty | 20 / 0 / 1.0 | 后端固定采样配置 |
| 思考 / reasoning budget | off / 0 | 后端模板和运行器 |
| KV cache K / V | q8_0 / q8_0 | 后端 |
| 投机解码 | draft-mtp，最大草稿2 | 后端 |

本次将前三项显式保存到OpenWebUI的Qwen模型默认参数；后端原先已经一致。
核对用户此前那次914-token请求，客户端没有传入采样覆盖项，后端命令已使用表中数值。
因此这次保存默认值本身不代表画图质量或TPS会提高。MiniCPM未在参考仓库中列出，保留其已验证配置。
OpenAI文本接口不接受`top_k`、`min_p`、`repeat_penalty`扩展字段，所以这些保留在后端，不作为WebUI自定义请求字段发送。

Jetson的适配差异仍保留：上下文131072而非200000，SSD专家缓存，batch/ubatch为2048/8而非384/384，
Flash Attention显式on而非原始命令auto，seed固定42（原配置未指定），输出上限7680（原配置未指定）。
不把这套部署描述成原机器的完全复现。刷新页面、新建Qwen对话即可使用模型默认值；
若手动设置过对话或个人级参数，先清除对应覆盖值。
标准测试只发送`Generate an SVG of a pelican riding a bicycle.`，不附加系统提示或历史聊天。
参数回读证据见[参考默认值核验](../reports/2026-10-21-openwebui-reference-defaults/verification.json)。

实际网页测试发现：v0.12.3默认会向普通UI聊天注入内置工具，而nx5文本接口明确拒绝tools。
因此通过OpenWebUI自身API，为两个现有模型ID保存了文本能力配置，`builtin_tools=false`，
同时关闭vision、file_context、web_search、image_generation、code_interpreter、terminal。
这些设置写入持久化模型配置，不修改OpenWebUI源代码，不把工具调用伪装成文本请求。
详见[models.json](../deploy/openwebui/models.json)。

部署代码提交：`4b46ced2085df02705b64e9c96c502b11b459dd0`；模型配置和验收在后续提交中记录。
复现顺序（新实例；已有容器或数据会拒绝覆盖）：

```bash
python3 scripts/nx5/deploy-openwebui.py --commit <包含release.json的固定提交>
python3 scripts/nx5/deploy-openwebui.py --commit <同一固定提交> --apply
# 等待容器healthy，再以管理员身份应用模型能力配置
python3 scripts/nx5/configure-openwebui-models.py \
  --profiles deploy/openwebui/models.json --output /tmp/openwebui-models-check.json
```

模型配置通过认证API修改；不直接编辑数据库。重新部署/升级时保留data目录和私有密钥。
停用本实例只需停止`nx5-openwebui`容器，不要删除数据，也无需停nx5推理API。
