## MTP 与 SSD 兼容修复

[补丁0004](../patches/0004-qwen-mtp-les-window.patch) 修复两处问题：

1. MTP图也需要按批宽选择每层decode缓存视图；原代码一直引用prefill视图。
2. 专家缓冲必须同时按**量化类型与字节步长**分组。MTP的Q3_K与主干IQ3_S每专家
   都占450560 bytes，但编码不同；只按字节数分组会使窗口继承错误的量化类型。

诊断首次无效值出现在MTP的`ffn_moe_gate-40`。仅修复视图时草稿概率为NaN，
接受率0/80；切到CPU采样仍复现，排除了仅是GPU采样的问题。
补齐量化分组后，短问答草稿接受22/38（57.9%），无NaN候选概率，
与关闭MTP的贪心答案逐字一致，17×23也正确回答为391。
详见 [短问答对照](../reports/2026-10-21-qwen36-nx5/qa-comparison.json)。

运行库在独立目录`mtp-les-lib-v3`构建，组合原有补丁0002、0003与本次0004。
上游源码目录及MiniCPM库未改写。来源和编译命令见
[构建记录](../reports/2026-10-21-qwen36-nx5/mtp-les-build-fixed.json)。
短诊断的加载、缓存与日志级别不同，不能用它们直接估算MTP的稳态加速倍数。

## 运行入口

在nx5上运行：

```bash
cd /home/nx/github/qwen38-kvmem/qwen36-audit-20261021
python3 scripts/qwen36/run-ssd.py samples/pelican-standard.txt \
  --tag my-qwen36-pelican --tokens 7680
```

入口先校验权重拆分与运行库，确认原业务空闲，再获取`nx5-igpu`的中央独占租约。
结束后确认推理进程退出并释放租约。它不会强杀别的任务；已有业务运行时会拒绝启动。
日志与实际命令保存在`validation/`。本轮是独立CLI试验入口，尚未新增Qwen HTTP服务。

复建辅助脚本：`scripts/qwen36/download.py`、`prepare-ssd.py`、`build-mtp-les.py`。
下载器以[固定配置](../configs/qwen36-iq4xs-8k.json)为准；构建器复用已审计的nx5 Ninja对象和CUDA库，
不是任意版本llama.cpp的通用安装器。
