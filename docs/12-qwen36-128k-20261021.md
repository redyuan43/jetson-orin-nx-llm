# Qwen3.6 在 nx5 上的 128K 容量验证

**Qwen3.6-35B-A3B MTP UD-IQ4_XS 已在 nx5 跑通 131072 token 上下文容量。**
保持 window128 / bank64 / MTP draft2，无需进一步缩小专家缓存、删除专家或降低量化精度。
本轮只把运行参数 `ctx` 从8192改为131072，保存为独立的
[128K配置](../configs/qwen36-iq4xs-128k.json)，原8K默认入口保留。

验收包括容量分配、**8218 token实际输入**的六字段检索，以及完整标准鹈鹕SVG生成。
**尚未测试填满128K的输入、接近容量上限的生成速度或长期多轮常驻。**
131072是输入、历史与输出共用的总容量，不能把全部空间都用作输入后再额外要求长输出。

## 实测结果

| 测试 | 输入 / 输出 token | 提示处理 | 生成速度 | 进程总耗时 | 最低可用内存 |
|---|---:|---:|---:|---:|---:|
| 128K容量短问答 | 84 / 41 | 6.32秒 | 12.09 token/s | 18.55秒 | 2.03 GiB |
| 128K容量、约8K实际输入检索 | 8218 / 102 | 283.68秒 | **16.14 token/s** | 298.69秒 | **1.93 GiB** |
| 128K容量、完整标准鹈鹕SVG | 23 / 1976 | 2.02秒 | **17.31 token/s** | **125.26秒** | 1.99 GiB |
| 前轮8K容量、同一标准鹈鹕SVG | 23 / 1976 | 1.86秒 | 17.85 token/s | 138.79秒 | 3.51 GiB |

三次新运行均正常结束、无输出截断、OOM计数增量为0，中央GPU租约已释放。
nx5没有启用swap。进程总耗时包含加载与退出；各次文件缓存和加载时间不同，
不能根据128K的总耗时较短就判断它更快。相同SVG的生成速度单次差约3%，没有重复多次统计。
短问答仅41个输出token，不用于估算稳态速度。

检索资料包含227条合成记录，六个目标位置约在全文3%、20%、40%、60%、80%、97%。
六项verification字段全部精确匹配，输出也是合法JSON。
该测试只证明这一条输入的检索成功，不代表全部长上下文任务的准确率。
前置处理速度为28.97 token/s；长文的主要等待时间是读取和处理输入，
不能把16.14 token/s的回答速度理解为整篇资料的处理速度。

标准鹈鹕题严格使用：

```text
Generate an SVG of a pelican riding a bicycle.
```

关闭思考，保留同一seed42、采样参数与MTP设置。
128K输出与8K输出**逐字节相同**：4001 bytes，SHA256
`d1872c1b1b58098947583f60c39b6865abfe1d3d4b5aafeb70b01d63f678e336`。
MTP两次都是1245/1464＝85.04%。因此本题没有观察到输出质量变化；
原图前轮与车架断开、缺少腿脚的缺陷也同样保留。
更大的上下文不会自动改善这道短提示绘图题。

## 内存与模型支持

[官方模型卡](https://huggingface.co/Qwen/Qwen3.6-35B-A3B)和本地GGUF元数据都标明
原生上下文262144，因此131072在原生范围内，无需额外设置RoPE缩放。
这个结论是模型规格；本机能否运行则以本轮实测为准。

| 部分 | 本轮128K配置 |
|---|---:|
| SSD上的完整专家文件 | 约14.53 GiB，全部专家保留 |
| 专家映射缓冲 | 7739.50 MiB，约7.56 GiB |
| 其余权重文件 | 约2.43 GiB |
| 主模型10层普通注意力KV，q8_0 | 1360 MiB |
| MTP一层KV，f16 | 256 MiB |
| 主上下文递归状态缓冲 | 188.44 MiB |

两个上下文的KV合计1616 MiB，约1.58 GiB；8K时对应85+16＝101 MiB，
因此扩到128K增加约1515 MiB。还需要计算缓冲、回滚状态、提示缓存和操作系统内存，
不能只把表中的项目相加当成总峰值。
正常提示检查点仍限制为2，提示缓存预算64 MiB。
源码中的混合模型检查点使用`PARTIAL_ONLY`保存递归状态，不复制普通注意力KV。

本轮没有进一步减少专家驻留窗口，所以SSD加载策略与8K相同。
权重、模板、运行库和修复补丁仍使用[前轮已校验版本](11-qwen36-nx5-ssd-20261021.md)。
扩大容量后，实际历史继续增长仍可能增加注意力计算时间和其他临时开销；
不能把上述短提示速度或剩余内存直接当成满128K时的承诺。

## 使用与复核

128K配置已同步到nx5独立Qwen目录。运行：

```bash
cd /home/nx/github/qwen38-kvmem/qwen36-audit-20261021
python3 scripts/qwen36/run-ssd.py samples/pelican-standard.txt \
  --config configs/qwen36-iq4xs-128k.json \
  --tag my-qwen36-128k-pelican --tokens 7680
```

入口校验权重与运行库、检查机器空闲并获取独占租约，结束后释放。
当前仍是CLI部署；本轮未新增HTTP服务，也未改变MiniCPM的64K固定配置。

[完整评估结果](../reports/2026-10-21-qwen36-128k/assessment.json)包含准确率、速度、内存、
MTP、文件校验与租约结果。
[原始日志](../reports/2026-10-21-qwen36-128k/validation/)保留实际命令、逐次内存采样及原始输出；
在本地运行`python3 reports/2026-10-21-qwen36-128k/assess.py`可重新核对。
